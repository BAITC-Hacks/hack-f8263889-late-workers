# Late Workers — фронтенд

React 19, TypeScript, Vite, Tailwind 4, TanStack Query, Zustand, React Hook Form и i18next. Реализованы регистрация бизнеса и студента, вход, восстановление сессии, кабинеты, выход и доступ по ролям. Интерфейс доступен на русском, казахском и английском, в светлой и тёмной темах.

Текущий этап работает с моками по новому контракту `/api/auth/*`. Существующий FastAPI backend пока использует другой контракт; интеграция с реальным API остаётся отдельной проверкой после его готовности.

## Запуск

Команды выполняются из `frontend/`; нужен Node.js 22.12+ и Yarn.

```bash
yarn install --frozen-lockfile
test -f .env || cp .env.example .env
yarn dev
```

Если `.env` уже существует, обновите нужные переменные вручную. Откройте [localhost:5173](http://localhost:5173): гость попадёт на `/login`. Backend для сценариев авторизации на моках не нужен.

| Роль                    | Email              | Пароль       |
| ----------------------- | ------------------ | ------------ |
| Бизнес, Кофейня «Зерно» | `owner@zerno.kz`   | `coffee2026` |
| Студент, Арман Сейтказы | `arman@student.kz` | `arman2026`  |

Можно регистрировать новые аккаунты. Моки хранят аккаунты и сессии в памяти Vite: обновление страницы сохраняет вход, перезапуск Vite сбрасывает данные и возвращает только демонстрационные аккаунты.

## Переменные окружения

| Переменная         | Значение по умолчанию   | Назначение                                                        |
| ------------------ | ----------------------- | ----------------------------------------------------------------- |
| `AUTH_MOCKS`       | `true`                  | Включает mock API только при запуске Vite в режиме `development`. |
| `API_PROXY_TARGET` | `http://localhost:8000` | Backend для прокси `/api`; путь передаётся без изменений.         |
| `VITE_APP_ENV`     | `development`           | Метка окружения: `development`, `staging` или `production`.       |

`AUTH_MOCKS` и `API_PROXY_TARGET` читает сервер Vite; эти значения не становятся переменными браузерного приложения. В Docker Compose адрес прокси установлен в `http://api:8000`; значение `AUTH_MOCKS` можно передать через окружение команды Compose. Полный стек из корня репозитория запускается командой `make docker-up`.

Для подключения совместимого backend:

```bash
AUTH_MOCKS=false API_PROXY_TARGET=http://localhost:8000 yarn dev
```

Повторите регистрацию обеих ролей, вход, обновление страницы, проверки доступа и выход уже с реальным сервером. Успех mock-тестов не подтверждает совместимость с текущим FastAPI.

`yarn build` и `yarn preview` не включают mock API. В production хостинг должен направлять `/api` к совместимому backend и отдавать SPA для клиентских маршрутов. `VITE_API_URL` сохранился только для исходников старого health-демо; действующая авторизация его не использует.

## Сессия и маршруты

Все auth-запросы идут на относительный `/api` с JSON и `withCredentials: true`. Сервер устанавливает cookie `access_token` с `HttpOnly; SameSite=Lax; Path=/; Max-Age=604800`. В моках её значение — случайный идентификатор сессии. JavaScript не читает cookie, Bearer-заголовки и хранение токена в браузерных хранилищах не используются. Старый ключ `authToken` удаляется при старте приложения.

При запуске приложение запрашивает `GET /api/auth/me`: до ответа виден индикатор загрузки, без промежуточных редиректов. Начальный 401 означает гостя; другие ошибки открывают экран с повторной попыткой. Вход и регистрация сразу используют пользователя из ответа. Logout отзывает серверную сессию и очищает cookie. Последующий `401 UNAUTHORIZED` очищает состояние и ведёт на вход; `INVALID_CREDENTIALS` остаётся ошибкой формы, а 403 не завершает сессию.

| Маршрут              | Доступ                                  |
| -------------------- | --------------------------------------- |
| `/login`             | Вход гостя                              |
| `/register/business` | Регистрация бизнеса                     |
| `/register/student`  | Регистрация студента                    |
| `/business/*`        | Кабинет пользователя с ролью `business` |
| `/student/*`         | Кабинет пользователя с ролью `student`  |
| `/`                  | Вход для гостя или кабинет текущей роли |

Пользователь другой роли перенаправляется в свой кабинет. Авторизованный пользователь на странице входа или регистрации также переходит в кабинет. Старые демонстрационные и неизвестные адреса перенаправляются через `/`; исходники демо сохранены. Восстановление пароля, подтверждение email, редактирование профиля и команды не входят в этот этап.

## Проверки

```bash
yarn lint
yarn typecheck
yarn build
npx playwright install chromium
yarn test:e2e
```

`lint` проверяет исходники приложения, dev-middleware, браузерные тесты и TypeScript-конфигурации. `typecheck` проверяет приложение, Node-конфигурацию с mock-плагином и E2E-тесты. Playwright самостоятельно запускает Vite с моками на `127.0.0.1:5180`; порт должен быть свободен. Chromium устанавливается один раз, затем достаточно запускать `yarn test:e2e`.

Браузерные сценарии проверяют регистрацию и вход обеих ролей, атрибуты cookie и отсутствие токена в JavaScript, сохранение входа после обновления, выход, редиректы, ошибки 401/409/422/500, клиентскую валидацию, правила тегов, загрузку и повтор запроса сессии. Проверки интерфейса охватывают три языка, обе темы и ширины 375, 768 и 1920 px. При ошибках Playwright сохраняет скриншоты и trace; HTML-отчёт открывается командой `npx playwright show-report`.

## Структура и правила разработки

```text
src/common/            компоненты, общие className и утилиты
src/core/index.css     цветовые токены и базовые стили
src/core/api/          Axios, ошибки, SSE, события истечения сессии
src/core/query/        TanStack QueryClient и Provider
src/core/router/       маршруты приложения
src/modules/auth/      контракты, валидация, API, store, hooks, формы и кабинеты
src/modules/theme/     тема и переключатель
src/modules/*/         сохранённые демомодули
dev/authMock.ts        серверные моки авторизации для Vite
e2e/                   Playwright-сценарии
public/locales/        переводы ru, kk, en
```

Правила архитектуры и дизайна находятся в [AGENTS.md](AGENTS.md). Между модулями используйте публичные `index.ts`, внутри модуля — относительные импорты. Компоненты отвечают за JSX, hooks — за состояние и запросы, чистые функции — за валидацию и преобразования. Dev-моки напрямую импортируют только чистые типы и валидаторы авторизации, чтобы не загружать браузерный runtime в Node.

Для интерфейса используйте существующие `Page`, `Section`, `Stack`, `Card`, `Button`, общие классы и цветовые токены. Сохраняйте переводы, доступность форм и поведение тем; валидация браузера и моков опирается на одни правила. Старый MSW worker не запускается, хотя его исходники и зависимость сохранены для компиляции демомодулей.
